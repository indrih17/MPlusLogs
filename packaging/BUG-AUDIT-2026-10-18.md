# MPlusLogs audit — 2026-10-18

Release candidate: **MPlusLogs 0.5.29 / Companion 1.0.22**.

## Scope and method

Reviewed addon Lua, the clipboard exchange, WCL normalization and caching,
parallel profile and realm discovery, API quota accounting, GUI/authentication,
portable updates, packaging and release destinations. Three independent agents
audited separate areas, then cross-reviewed changes. The coordinator reviewed
the combined result against the external published checkout.

Each confirmed behavior fix has a regression that failed before its fix.
The baseline elevated suite ran 590 tests and exposed two errors from one
obsolete compatibility contract. The updated test uses the actual published
Companion protocol: an unsupported group request must produce an upgrade
message, preserve the requested roster and issue no WCL query. It must not
silently replace the requested group with its leader.

## Confirmed fixes

| Area | Failure | Result |
| --- | --- | --- |
| WoW identity | Unavailable/secret realm became the local realm | Reject unavailable identity instead of loading a same-name local character |
| Tooltip | Missing unit identity could reach role/key construction | Validate identity before using it |
| Access state | Hidden logs retained cached tooltip percentiles | Respect hidden, missing and empty profile states |
| Batch requests | Caller mutation changed pending roles/specs | Capture an independent request snapshot |
| Search freshness | Wrong-metric legacy profile counted as complete | Require the requested metric before skipping loading |
| Group roster | Same-name members could reuse one table twice | Match each previous roster member at most once |
| HTTP transport | Truncated reads escaped normal recovery | Return typed network error and settle admission as uncertain |
| Upstream schema | Invalid JSON escaped typed API handling | Safe schema error with batch backoff |
| Client credentials | Non-object/token-shaped reply caused a crash | Validate token response shape |
| Regional batch errors | Same realm/name in EU and US shared error lookup | Correlate region, realm and name |
| Retry cache | Non-string error metadata caused AttributeError | Discard invalid record and recover normally |
| Roster input | Null JSON member crashed queue merging | Validate members before merging |
| Redirected characters | New name/server could be exported under old identity | Validate name, region and realm before cache replacement/export; recover old contaminated caches |
| Authentication diagnostics | Header validation could echo a credential | Reject malformed Authorization before urllib; use generic errors |
| Sign-out | Failed persistence cancelled an active browser login | Cancel only after successful sign-out persistence |
| Completed reply | Locked last-result file discarded a ready reply | Keep UI and clipboard delivery available |
| Preferences | Failed watcher setup could restore stale OAuth tokens | Complete startup changes before committing current configuration |
| Portable updates | Corrupt DEFLATE escaped update recovery | Convert compression failure to a recoverable update error |
| OAuth expiry | Infinite/huge or boolean expiry escaped safe validation | Reject invalid/out-of-range expiry without replacing credentials |
| OAuth refresh | Malformed refresh token replaced usable credentials | Validate token content/shape before session persistence |
| OAuth callback | Non-ASCII state caused uncaught TypeError | Reject malformed state through the normal invalid-callback path |

## Release preparation

The release includes the pre-existing, reviewed optimization work in this
workspace: adaptive parallel fetching, measured WCL cost admission, resumable
realm discovery, primary-metric loading, WCL score corrections and bulk paste
handling. See `packaging/RELEASE-NOTES.md` for the proposed public changelog.

Added Wago integration for project `qKQgAENx`, using the existing validated addon
ZIP. The implementation follows [Wago's documented API](https://docs.wago.io/).
Its HTTP success contract follows the linked
[BigWigs packager](https://github.com/BigWigsMods/packager/blob/master/release.sh).
Wago receipts and pre-upload intent markers prevent automatic duplicate POSTs
after an ambiguous failure. Retry notes come from the addon's own GitHub release.

Only `CF_API_TOKEN` was present among repository Actions secret names during
preparation. `WAGO_API_TOKEN` is required for Wago publication. At the user's request,
its absence defers only Wago; GitHub and CurseForge publication continue. No credential values were read from GitHub or printed.
No live Wago POST has been performed. Offline uploader tests do not establish
that a live upload will pass platform validation or moderation.

## Remaining checks and future tests

- Live WoW validation of 60–100 applicant paste/render responsiveness, UI scaling,
  protected/secret API values and real third-party addon coexistence. Offline Lua
  mocks cannot establish game-client frame time or taint behavior.
- Verify actual WCL rename/transfer replies and realm aliases against production
  responses without weakening account, region or server-ID checks.
- Exercise a newly published Wago release end to end, including receipt recovery
  after lost responses. This requires configured credentials and release approval.
- Broader crash-injection tests around interrupted cache/SQLite writes and update
  process termination can further improve durability coverage.
